# Editing an entity happens in a modal, with no URL, and the forms have outgrown it

## Problem

Every edit form in the admin UI is a `Dialog` opened from local `useState`. The forms have
grown past what a modal holds: the grant definition dialog scrolls inside a fixed height
with the Save button floating over the "Priority" help text, the server group dialog stacks
three checkbox lists (servers, access approvers, query approvers) in one scroll box, and the
edit user dialog mixes roles, groups and two nested `AlertDialog`s. Nothing has a URL, so an
edit cannot be linked, bookmarked, reloaded or reached with the back button, and an E2E test
has to click through the list to open it.

Where the edit modals are today (state hook, then dialog component):

| Entity | List route | Edit modal |
|---|---|---|
| User | `front/src/routes/_authenticated/users/index.tsx` | `editUser` :77, `EditUserDialog` :516 |
| User group | `user-groups/index.tsx` | `editing` :55, `GroupDialog` :204 (shared with create) |
| Server | `servers/index.tsx` | `editDb` :285, `renameDb` :284, `approversDb` :283 (`EditServerApproversDialog` :684), `editSshServer` :282, `detailDb` :281 (`DatabaseDetailsDialog` :1388) |
| Server group | `server-groups/index.tsx` | `editing` :56, `ServerGroupDialog` :219 (shared with create) |
| Grant definition | `grant-definitions/index.tsx` | `editing` :133, `DefinitionDialog` :488 (shared with create) |
| Global parameter | `settings/index.tsx` | `editTarget` :752, inline dialog :843 |

`connections/$uid.tsx` and `queries/$uid.tsx` already show the target pattern for detail
pages (TanStack Router file routes).

## Decisions (Florent, 2026-11-24)

- **Edit forms only.** Create forms stay dialogs: `CreateUserDialog` (users :442),
  `CreateDatabaseDialog` (servers :899), the create mode of `GroupDialog`,
  `ServerGroupDialog` and `DefinitionDialog`, `AssignGrantDialog` (grants :434),
  `CreateRequestDialog` (grant-requests :348), `CreateKeyDialog` (api-keys :328).
- **Small edit forms get a page too.** The global parameter edit is a page, like the rest.
- **One page per server**, with sections, rather than one route per aspect.

## Proposal

Rule: **a form that edits an existing entity is a page with its own route.** A dialog stays
for a create form, a confirmation (delete, revoke, deactivate, deny, reset password, "you
are demoting yourself") or a one-shot reveal (the new API key secret in `ShowKeyDialog`).

1. Routes, as TanStack file routes under `front/src/routes/_authenticated/` (the route tree
   `routeTree.gen.ts` is regenerated by the Vite plugin):
   - `users/$uid.tsx`
   - `user-groups/$uid.tsx`
   - `servers/$uid.tsx`: one page with sections for what is split today across details,
     edit, rename, approvers and the SSH tunnel edit. Each section keeps its own Save where
     the API calls are separate today (rename, approvers, server fields). Rename keeps its
     own warning (CLAUDE.md: "the name in its own dialog, for its own warning"), as a
     confirmation on save of that section.
   - `server-groups/$uid.tsx`
   - `grant-definitions/$uid.tsx`
   - `settings/parameters/$key.tsx` for a global parameter
2. Each page loads the entity by uid with the existing React Query hooks, shows a loading
   state and a not-found state ("not found or archived" for a definition), and has Save and
   Cancel in a sticky footer. Save navigates back to the list; Cancel and the back button
   return without saving. The list's "Edit" action becomes a `<Link>`; the row name links
   too.
3. Extract each form body into a component (e.g. `front/src/components/<entity>/<Entity>Form.tsx`).
   Where a dialog serves both create and edit (`GroupDialog`, `ServerGroupDialog`,
   `DefinitionDialog`), the create dialog keeps wrapping that same form component and the
   edit page renders it without the `Dialog`. Drop the `editing` state from the lists. No
   behaviour change in the form itself: same fields, same validation, same API calls, same
   "send only what moved" logic on servers.
4. Grant definitions are immutably versioned: `$uid` resolves to the live row of the
   lineage. Saving creates a successor with a new uid, so the page goes back to the list,
   not to the old uid.
5. Keep every existing `data-testid` on the fields; rename the edit container testids from
   `*-dialog` to `*-page` (`edit-user-page`, `definition-page`, …) and update the E2E specs.
   Create dialogs keep their testids.
6. Layout: forms get the page width, long checkbox lists (servers, members, approvers) get a
   search filter and their own height instead of one shared scroll box.

## Tests

- E2E (`front/e2e/users.spec.ts`, `user-groups.spec.ts`, `servers.spec.ts`,
  `server-groups.spec.ts`, `grant-definitions.spec.ts`, `settings.spec.ts`): each existing
  edit case goes through the page instead of the dialog and still passes; create cases are
  unchanged.
- New E2E per entity: `page.goto('/<entity>/<uid>')` directly opens the filled form;
  reloading keeps it; the back button returns to the list without saving.
- New E2E negative cases: an unknown uid shows the not-found state, not a blank form; a
  viewer (non-admin) hitting an admin edit route gets the same access refusal as the list.
- New E2E: saving a grant definition lands on the list and the new version is listed; the
  old uid no longer resolves to an editable form.
- New E2E on `servers/$uid`: renaming asks for confirmation, and saving one section leaves
  the others' unsaved changes untouched.
- `bun run lint`, `bun run build` (type check) pass.
